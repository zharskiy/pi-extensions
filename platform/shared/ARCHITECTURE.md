# shared architecture

Pi-free, theme-free, host-free helpers that more than one extension, or an extension's `core/`, needs. It imports only `platform/pi-adapter/index.ts` and node built-ins, and every other layer may import it through `index.ts`, including an extension's `core/`. That is why the plugin contract types live here rather than in `platform/extension-manager/`: `core/` may not import the manager, but its plugins and events need the types.

## What may enter

A module belongs in `platform/shared/` only when all of these hold:

- It imports nothing but node built-ins, other `platform/shared/` files and `platform/pi-adapter/index.ts`, and from the adapter only types and the row geometry constants.
- No function takes a `Host` or an `AgentRuntime`; a module that needs one belongs to `platform/extension-manager/` (or to the extension).
- It paints no theme. Measuring text through `ThemeLike`'s `width` and `wrap` is fine; calling `fg`, `bg`, `bold` or `inverse` is not, and such a module belongs to `platform/ui-kit/`.

## Modules

Modules are grouped by concern in five folders, plus three single-purpose modules at the top; `index.ts` re-exports them all and stays the only import surface.

- `plugin/`, the contract between the extension manager and the plugins.
  - `plugin-contract.ts`: `Plugin` (its context carries `settingsErrors()`, the errors of the latest settings load), `Disable`, `Bus`, the service registry type, the event map type and `ExtensionPaths`; `platform/extension-manager/` implements them.
  - `settings-files.ts`: the schema type (a number rule may require a whole number, `integer: true`), `parseSettings`, `readText`, `readSettingsFile`, `SettingsScope` (`user` or `project`) and `settingsPath(location, scope, file)`, the one choice between `<agentDir>/<file>` and `<cwd>/.pi/<file>` that the reader, the writer, mcp-import and subagents share, `readSettingsFiles` and `loadSettingsFiles`, the user-then-project merge with its error list (with the file scope `"user"`, `FileScope`, a trusted project file is not read and, when it exists, is reported as ignored, for a setting a committed project file must not set for every project), and `writeSettingsFile(location, scope, file, text)`, the one writer of a settings file: a user file under the agent dir, its folder created, or a project file through `writeProjectFile`; it returns the path and throws on a failed fs step, so callers turn the error into their own message.
- `handoff/`, the handoff format. Extensions never deep-import each other, so the formats two of them share live here; session-limits and subagents share these.
  - `handoff-document.ts`: the handoff sections, `HandoffValidation`, `validateHandoff`, the `HandoffToolRows` type of the handoff tool's rows, the `HandoffSeedDetails` and `HandoffRequestDetails` types of the seed and request messages and their parsers `parseSeedDetails` and `parseRequestDetails`, next to their types as the channel parsers are (a seed names its origin explicitly, `{ from: "session" }` or `{ from: "agent", id, link }`; a manual request carries its `command` label, so the row names the command without knowing it), their custom types `HANDOFF_REQUEST_TYPE` and `HANDOFF_SEED_TYPE`, `handoffRoot` (`<OS temp dir>/pi-handoff`) and `handoffPath` (`<handoffRoot>/<session id>/main-handoff.md` or `<agent id>-handoff.md`).
  - `handoff-limit.ts`: the main session's handoff thresholds and the one level evaluator. `Limits` is the settings type and `limitsSchema` its one validity rule (ratios above 0 and at most 1, token caps above 0 and at most 100,000,000), which session-limits reads its settings with and `parseLimits` checks the `LIMITS_CHANNEL` payload with (all four keys, no error, or nothing); `HandoffLimit` the request and warn lines (subagents builds its agent limit on it), `mainLimit` the limit of a window under the limits (the soft and hard thresholds; none for an unknown window) and `limitLevel` (unknown, normal, soft or hard for a token count); session-limits decides with `limitLevel(tokens, mainLimit(window, limits))` and the footer tones its context figure with the same call. `workingContextText(tokens, request)` is the plain `working context X of Y` (`WORKING_CONTEXT` the label) that the footer label, the subagents agent view and `agent_status` share.
  - `handoff-prompt.ts` and `handoff-prompt.md`: the handoff instruction template (the only non-TypeScript file here, a prompt asset read by its own module through `import.meta.dirname`), the `HandoffAudience` type (statuses, status hint, reader, extra rules, next hint), `handoffInstruction` (which loads the template itself and fills it from the audience it is given), `handoffRetry` and `seedText`. The audiences and successor prefaces belong to their consumers: the main audience and the session preface to session-limits, the agent audience and the chain preface to subagents; each passes its audience's `statuses` to `validateHandoff`.
  - `handoff-seam.ts`: the wording of the rule that closes a handed-off transcript, `seamLabel(cause)` (`handed off · <cause>`) and `LIMIT_SEAM` (`handed off · context limit`); session-limits labels the main session's seam with them (the command name for `/handoff` stays in session-limits, which passes it as the cause), and the subagents view draws `LIMIT_SEAM` between chain links.
  - `handoff-tool.ts`: `handoffTool`, the `handoff` tool both consumers use (a `target()` for the path and whether a handoff was requested, a `validate`, injected rows and an `onSaved` callback; it refuses unless requested, writes the content, validates it and reports the result).
  - `handoff-file.ts`: `writeHandoffFile`, the one way both consumers write a handoff file: it creates the folder and writes, and when the folder vanished in between (an empty one may be cleared by another process) creates it and writes once more.
- `agent-runs/`, the agent runs on disk. Subagents writes them, and an extension that reads them uses the same layout and keep rule.
  - `agent-runs.ts`: the layout and the part of a run manifest that decides how long a run is kept: `sessionStem` (a session file without `.jsonl`), `runsDir` (`<stem>/agents`), `fallbackStemsRoot` (`<agentDir>/pi-subagents`, the stems of sessions without a file), `sessionRunsDir`, `RUN_MANIFEST` (`manifest.json`), `RunManifest` (the chain links `predecessorId` and `successorId` and the `worktree` with its `RunCleanup`), which the manifest writer satisfies at compile time, and `runRules(manifest)`, the links and whether the run must be kept (a worktree whose cleanup is not `removed`).
- `channels/`, how extensions talk at run time.
  - `host-channels.ts`: the channel names of pi's shared event bus (`pi:busy`, `pi:background-work`, `pi:awaiting-input`, `pi:handoff-pending`, `pi:held-results`, `spending:usage`, `spending:totals`, `session-limits:limits`), their payload types and parsers, and the two sums of a `spending:totals` payload, `agentsSpend` (the sources) and `sessionSpend` (main and the sources), which the footer and spending's own status both use. Two of them look alike and answer different questions:
    - `pi:busy` `{ source, busy }`: agents open. Work a source runs is still going (subagents while any agent is open); session-limits holds its switch and notifications its idle notice on it, both through `trackBusy({ onBusy, onQuiet })`, which keeps the set of busy sources behind a `receive` handler for `Host.subscribe`, calls `onBusy` for every busy signal and `onQuiet` only when a known source ending empties the set, and lists the sources with `sources()`.
    - `pi:background-work` `{ source, count }`: results not yet answered by the main session. The units of work that will reach the main session on their own (subagents counts background batches until the model starts a reply after their wake); a consumer keeps the last count per source and treats the session as settled only when every count is 0 (the transcript's answer rule, which also reads the counts at the end of each reply to tell the final answer). A source should drop a unit no later than the start of the reply that answers it, so a count read at that reply's end is already current.
  - `pi:handoff-pending` `{ source, pending }` (session-limits, from the handoff request until it is cancelled, given up or the switch fails) and `pi:held-results` `{ source, text }` (everything a source holds back while a handoff is pending instead of starting a run, in one text): session-limits carries the held texts into the new session's seed.
  - `status-keys.ts`: the status-key roles, never a concrete key: `HINT_STATUS_PREFIX` (`hint:`, a status the footer draws in its hint row and leaves out of its status lines) and `MIRROR_STATUS_PREFIX` (`mirror:`, a status that mirrors a figure the footer draws itself, hidden by it); each extension builds its own key under one of them.
- `text/`, theme-free text helpers.
  - `format.ts`: `formatTokens` and `formatDuration` (footer, working indicator, context, subagents); `formatWindow`, the context window in whole thousands or tenths of a million (footer, context); `errorText` (the settings loader, session-limits, subagents); `homeRelative`, a path under the home directory as `~/…` (mcp-import, the handoff rows); `shortPath`, a path relative to the working directory or else home-relative (transcript rows, context's memory files); `noun` and `counted` (`1 agent`, `3 agents`); `formatCost` (`$0.04`, `<$0.01`, zero omitted) and `formatMoney` (the same with zero as `$0.00`; footer, spending); `formatPercent` (`42%`, or `42.5%` with one digit, never `-0%`; whole percentages round as `Math.round` does, so `-0.5` reads `0%`; it, `formatDuration` and `formatCost` format a value that is not a finite number as empty; the cache tone, footer, context).
  - `front-matter.ts`: `parseFrontmatter` splits a `.md` file into its `---` header data and the trimmed body (CRLF read as LF; the closing `---` may carry trailing spaces and must end its line); subagents agent files, the autosetup skill scan and style files read front matter only through it.
  - `text-layout.ts`: `DOT`, the one ` · ` separator; `ELLIPSIS`, pi's ASCII `...` and the only cut mark; `cutStart`, a cut at the start by columns; `prefixed`/`padded`, wrapped lines behind a lead; `fixedBlock`, text wrapped to exactly N rows with the last cut by `...` and short text padded with blank rows; `padRows`, lines padded with blank rows or cut to exactly N.
- `cache-hit.ts`: `reportedCache`, `cacheHitPercent`, `sessionCacheHit` over the adapter's prompt token figures; its colour is `platform/ui-kit/cache-tone.ts`.
- `guards.ts`: `isPlainObject`, `isStringArray` and `isFiniteNumber`, the guards the parsers and the extensions share.
- `project-dir.ts`: owns `<cwd>/.pi/`, so no caller builds a `.pi` path to write to or can forget the `.gitignore`. `projectPath(cwd, relativePath)` resolves a path under it (`settingsPath` and subagents' project agents folder use it); `ensureProjectSubdir(cwd, relativePath, { ignored })` creates a folder under it and returns its path (worktrees); with `ignored` it also writes the folder's own `.gitignore` (`*`) when missing, which keeps the folder out of git even under a tracked `.pi/`; `writeProjectFile(cwd, relativePath, text)` writes a file under it, creating its folders, and returns the path (`writeSettingsFile` for `/agents setup` and `/mcp-import`). Both creators go through the private `ensureProjectDir`: when `mkdirSync` reports that it created `.pi/`, it writes `.pi/.gitignore` with `*` (which hides the file itself too), never over an existing one; a `.pi/` that already exists is left untouched, so a user who deletes the file to track `.pi/` never gets it back. A failed fs step throws (`.pi` being a file gives `EEXIST`).

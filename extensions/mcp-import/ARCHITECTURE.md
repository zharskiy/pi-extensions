# MCP-import architecture

## Boot

`index.ts` exports `api/extension.ts`, a `createManagedExtension` call with namespace `pi-mcp-import` and one plugin, `mcpImportPlugin` (`api/plugin.ts`). Its `enable` calls `createMcpImport(host, homedir())`, which registers the `/mcp-import` command and returns nothing to undo. No settings, no channels, no session entries.

`api/plugin.ts` owns the command: argument dispatch, the trust check for a project write, the notifications and the picker call. The flow itself is in `core/import-flow.ts`: `prepareImport` reads the sources and the target and plans one source and scope pair, `surveyImports` prepares all four pairs for the interactive pick and scans them (`pairs`, `untrusted` or `empty`), `selectedPlan` re-plans a pair for the picked servers and reports the unchecked ones as skipped (`not selected`), and `writeImport` writes the target, creating its folder. It writes only the target: `<agentDir>/mcp.json`, or `<cwd>/.pi/mcp.json` with `project` in a trusted project, plus `<cwd>/.pi/.gitignore` (`*`) when that write creates `.pi/`: `writeImport` hands the pair's scope to `writeSettingsFile` from `platform/shared` and never builds the `.pi` path itself, and returns a failed write as a `cannot write <path>: <error>` string.

## Runtime

- One command, `/mcp-import [<claude|cursor> [project] [apply]]` (`core/args.ts` parses and completes it). With arguments it does a dry run, or writes with `apply`. Without arguments, in tui mode, it picks interactively (`surveyImports` in `core/import-flow.ts` plans and scans, `ui/pick.ts` shows the forms): it plans every source and scope pair (Claude Code and Cursor, user and project), keeps the pairs that would add a server (project pairs only in a trusted project) and, with two or more left, asks which with a `selectForm` (`Claude Code · user`, `3 new: … → <target>`). Then a `multiSelectForm` lists the servers to add, all checked (`a` all, `n` none, Enter adds), each row with its transport and a sign-in or notes marker. Unchecked servers are reported as skipped (`not selected`); nothing checked writes nothing. Esc on either form cancels silently. If nothing can be imported it says so, naming the checked files or that the servers are already present, or that the only servers are in an untrusted project. Outside tui, with no arguments, it fails with the usage line. `core/sources.ts` reads the tool's files for the scope: Claude Code user scope is the top-level `mcpServers` of `~/.claude.json`; its project scope is `projects["<cwd>"].mcpServers` of the same file (the cwd or its real path; Claude's local scope, which wins on a name clash) then `<cwd>/.mcp.json`; Cursor is `~/.cursor/mcp.json` or `<cwd>/.cursor/mcp.json`. A file that cannot be parsed, or whose `mcpServers` is not an object, is a warning; a missing file is skipped. The server pick is the ui-kit multi-select, so its `a` and `n` match `KeyPress.shortcut` and work in a Cyrillic layout.
- `core/convert.ts` turns one entry into pi's shape, keeping only fields pi knows (`type`, `command`, `args`, `env`, `cwd`; `type`, `url`, `headers`) and recording a note for every rewrite or drop (Claude's `${VAR:-default}`, millisecond `timeout`, `headersHelper`, `oauth`; Cursor's `${env:X}`, `${userHome}`, `envFile`, `auth`), or a reason to skip it (`sse`, `ws` and other types, no `command` or `url`, a bad name, Cursor's `${workspaceFolder}`).
- `core/plan.ts` merges the converted entries into the target text (`<agentDir>/mcp.json`, or `<cwd>/.pi/mcp.json` with `project`): a name already present, also one that differs only in `-` and `_`, is skipped, and every other key of the file and its indentation are kept; a target that is not valid JSON stops the import. `ui/report.ts` builds one notification, prefixed `pi-mcp-import:` like every notice of the extension (problems as warnings, usage and write errors as errors): the dry run lists the entries, notes and skips and writes nothing; `apply` and the interactive pick write the file (the interactive report starts `added N servers to <target>`, without a command echo) (a project write needs a trusted project) and says to `/reload` and check with `/mcp`, listing HTTP servers without an `Authorization` header for sign-in. No settings, no state.

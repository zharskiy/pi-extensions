# Footer architecture

`index.ts` re-exports `api/extension.ts`, which builds the extension with `createManagedExtension` (namespace `pi-footer`, no settings) and one plugin, `footerPlugin` in `api/plugin.ts`. The plugin keeps the last spending totals and the last session-limits settings through `watchChannel` (`core/status.ts`, subscribes to a bus channel and keeps the last payload its parser accepts), installs the footer at session start and draws it with `renderFooter` (`ui/render.ts`) over the state `footerState` (`core/segments.ts`) reads from the host on every render. Its `enable` returns nothing to undo.

- Replaces pi's footer (`HostUi.setFooter(render)`, tui only) with a block aligned to the composer prompt (`PAD`, one space, the composer margin) that starts and ends with one blank line (so pi's command list never touches it) and has three lines. Line 1: folder, `on <branch>` and the session name on the left, the model name and `thinking <level>` on the right. Line 2: `context 42,318 · 24% of <base>` (the exact token count with a thousands separator, then the percent; the count is dropped together with `of <base>`, before the percent) and the session cache hit rate (`cache 73%`, hidden until the session reported cache activity) on the left, the session money on the right (token total, then the total cost; when agents spent something `$main main · $agents agents · $total total`, and a subscription session marks the total `on subscription`, `on sub` when narrow). Line 3: the hint row, the `app.thinking.cycle` key hint (`keyHints`, hidden for a model whose `reasoning` is false) then the subagents status. Then the other extensions' status texts, one line per key sorted by key, after a blank line, without spending's own `pi-spending` status (`SPENDING_STATUS_KEY`) and without the agents hint key (`AGENTS_HINT_KEY`, `pi-subagents`), which the hint row takes.
- Colour: a neutral hierarchy of existing theme tokens. `text` for the live figures (context count and percentage, total cost; `muted` for the total on a subscription), `muted` for identity (folder, branch, session, model, the cache figure) and `dim` for labels and separators. The one accent is the `thinking<Level>` token on the level word. Hue marks state only, the context: the count, the percentage and `of <base>` turn `warning` at `>= 70 %` and `error` (count and percentage bold) at `>= 90 %` of the base. The base is the context window; when session-limits has published its settings (`LIMITS_CHANNEL`, parsed by `parseLimits`) it is the handoff point, the hard threshold of `thresholdsFor(window, limits)` computed at render time from the live window, with `warning` from the soft threshold and `error` from the hard one, and the percentage may pass 100. Without a payload the window thresholds apply. The cost is never coloured. The single separator is ` · ` (`DOT`); there are no parentheses and no branch-token fallback.
- `ui/layout.ts` fits each line to the width. A `Segment` is a styled text with a drop priority (lower drops first, `Infinity` never) and an optional `next` form it steps down to instead of vanishing (`on subscription` to `on sub`, the `total` label going with the cost split); `spread` puts the left segments left and the right ones right-aligned and drops by priority across both sides until the line fits, `spread` with an empty right side fits the left-aligned hint row, and when only the never-drop segments remain and still do not fit the left side is cut with `theme.truncate`. Drop order, line 1: session name, thinking level, branch; line 2: token total, `on subscription`, cache, the cost split, `of <base>`; line 3: the cycle hint, then the agents hint.
- Cost and tokens come only from `spending:totals` (`TOTALS_CHANNEL`, parsed by `parseTotals`): the footer keeps the last payload, so a render reads only cheap live values (`Host.context()`, `mainRequestUsage()`, `model()`, `thinkingLevel()`, `sessionName()`; the adapter memoises `context()` on the session leaf id and the model, as pi's own footer does, and `mainRequestUsage()` on the session id, file and leaf id). Until spending publishes the money segments are hidden. The footer re-renders when totals or session-limits' settings (`LIMITS_CHANNEL`) arrive, on idle and on git branch changes.
- Placement: the adapter draws the block as the below-editor widget `pi-footer` and installs an empty component in pi's footer slot (pi draws its built-in footer whenever the slot is unset; the empty component also hands the adapter pi's `footerData` for branch and statuses). Order is editor, notices, footer block, then the agent panel. pi keeps below-editor widgets in first-set order and clears them all before every `session_start`; the footer sets its widget in its `session_start` handler and the adapter only re-renders it while it is mounted, so the order rests on timing, not on load order.
- Notices (`HostUi.setNotice`) sit between the editor and the footer block: while the footer widget is mounted it draws every notice (sorted by key, indented by `PAD`) as its first lines. Notices are not statuses, so the footer's status lines never repeat them.
- The adapter (`platform/pi-adapter/ui/footer.ts`) truncates every line to the width, re-renders on git branch changes and on `refresh()`, and drops the branch subscription when pi disposes the footer.

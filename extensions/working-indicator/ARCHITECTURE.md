# working-indicator architecture

- `index.ts` re-exports the default of `api/extension.ts`, which calls `createManagedExtension` with the namespace `pi-working-indicator` and one plugin, `workingIndicatorPlugin` (`api/plugin.ts`). The plugin's `enable` registers the host handlers and returns nothing to undo. No settings, no bus, no services.
- Active only in `tui` mode. The spinner is pi's own braille spinner; the extension never replaces it (the contract has no call to), so pi keeps colouring its frames with the editor's border colour (thinking level, bash mode).
- The clock counts the current prompt (one agent run), not a turn. The first `Host.onAgentStart` of a run (skipped outside `tui`, so no interval runs in other modes) records the start (`startRun`, `core/indicator-state.ts`) and reads pi's `app.interrupt` key once through `HostUi.keyText`; repeated `agent_start`s inside the run (retry, compaction, continuation) are ignored. An unref'd interval rewrites `HostUi.setWorkingMessage` every `TICK_MS` (1 s), even while the row is hidden and only when the text changed, as `<verb> · <elapsed> (<key> to interrupt)` (`workingText` and `interruptHint`, `ui/indicator-text.ts`): the time from 1 s on in `formatDuration`'s format (`12s`, `1m 5s`), the hint dim.
- The verb comes from `VERBS` (`ui/indicator-text.ts`): `pickVerb` picks one at random when a run starts and the one-second tick picks another every `VERB_MS` (8 s, `rotateVerb`), so the verb stays put between rotations and through every phase; the message is the bare verb (`Pondering`), since pi's spinner already animates before it. The message names no tool; the transcript's tool rows do. pi cuts the line on a narrow terminal.
- The row is drawn by pi inside the input's top rule (the composer's editor embeds it), not in a separate line above the editor.
- Visibility follows `Host.onPhase` (`isVisibleIn`): entering `writing` calls `HostUi.setWorkingVisible(false)`, and leaving it calls `setWorkingVisible(true)`; the tick kept the message current while hidden. pi re-shows the row at once while a run is active (`isStreaming`), so the row returns as soon as assistant text stops, in the same turn. Only transitions call pi, so a run without text never toggles it. `onPhase("idle")` (after the `onIdle` handlers of `agent_settled`) stops the interval, restores pi's visibility flag if it was hidden, and restores pi's default message. Shutdown stops the interval and clears the message; pi resets the flag itself on session switch and reload.
- Only the main session drives it: phases come from the main session's pi events, child sessions run in their own `AgentSession` with no-op working UI, and the extension subscribes to no bus or channel. Nothing is persisted.

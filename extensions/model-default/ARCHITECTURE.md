# model-default architecture

- `index.ts` re-exports the default of `api/extension.ts`, which calls `createManagedExtension` with the namespace `pi-model-default` and one plugin, `modelDefaultPlugin` (`api/plugin.ts`). The plugin's `enable` registers one handler and returns nothing to undo. No settings, no bus, no services, no commands.
- `Host.onModelSelect` fires on pi's `model_select` with sources `set` (the selector's Enter or Ctrl+S, `/model <name>`, an extension's `setModel`) and `cycle` (Ctrl+P), passing an opaque `provider/id` ref; the adapter drops `restore`. The handler awaits `Host.saveDefaultModel(ref)` on every one, so the most recent choice is always the default. Pi emits the event only when the model actually changes and never at startup or resume, so starting or resuming a session saves nothing. Another extension's model switch (such as a handoff restoring the previous session's model) is a `set` like any other and moves the default too.
- The write lives in the adapter (`platform/pi-adapter/runtime/default-model.ts`), the only layer allowed to import pi: it goes through pi's own `SettingsManager` into the global `<agentDir>/settings.json` and writes `defaultProvider` and `defaultModel`. When the session has a model scope (`enabledModels` or `--models`) without the model and `enabledModels` is non-empty and lacks it, the ref is appended to `enabledModels`, as Ctrl+S does; unlike Ctrl+S, the running session's Ctrl+P cycle gains it only from the next session. The thinking level is never touched. Pi re-reads the file under its lock and writes only the fields it changed, so the other keys and the running pi's later saves keep the value.
- The running pi's in-memory settings, and so the selector's `default` mark, see the change from the next session (`/new`, `/resume` or a restart). A project `.pi/settings.json` that sets `defaultModel` still wins over the global default, as it does for Ctrl+S.
- A failed save is data: `saveDefaultModel` resolves to the error text, and the plugin shows it as a `pi-model-default: <ref> is not saved as the default model: <reason>` warning through `HostUi.notify`. The session keeps the selected model either way.
- Only the main session drives it: the adapter never boots an extension inside a subagent session, and children get their model at creation, so a subagent's model never reaches the default. Nothing is kept in memory.

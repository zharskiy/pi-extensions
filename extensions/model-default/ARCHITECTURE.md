# model-default architecture

- `index.ts` re-exports the default of `api/extension.ts`, which calls `createManagedExtension` with the namespace `pi-model-default` and one plugin, `modelDefaultPlugin` (`api/plugin.ts`). The plugin's `enable` registers two handlers, one for the model and one for the thinking level, and returns nothing to undo. No settings, no bus, no services, no commands.
- `Host.onModelSelect` fires on pi's `model_select` with sources `set` (the selector's Enter or Ctrl+S, `/model <name>`, an extension's `setModel`) and `cycle` (Ctrl+P), passing an opaque `provider/id` ref; the adapter drops `restore`. The handler awaits `Host.saveDefaultModel(ref)` on every one, so the most recent choice is always the default. Pi emits the event only when the model actually changes and never at startup or resume, so starting or resuming a session saves nothing. Another extension's model switch (such as a handoff restoring the previous session's model) is a `set` like any other and moves the default too.
- The write lives in the adapter (`platform/pi-adapter/runtime/default-model.ts`), the only layer allowed to import pi: it goes through pi's own `SettingsManager` into the global `<agentDir>/settings.json` and writes `defaultProvider` and `defaultModel`. When the session has a model scope (`enabledModels` or `--models`) without the model and `enabledModels` is non-empty and lacks it, the ref is appended to `enabledModels`, as Ctrl+S does; unlike Ctrl+S, the running session's Ctrl+P cycle gains it only from the next session. Pi re-reads the file under its lock and writes only the fields it changed, so the other keys and the running pi's later saves keep the value.
- `Host.onThinkingSelect` fires on pi's `thinking_level_select` for a level someone set: the thinking selector's Enter or Ctrl+S, Shift+Tab, `/thinking <level>`, an extension's `setThinkingLevel` (such as a handoff restoring the kept level in `session_start`). The adapter leaves out the reset pi applies inside a model switch and any event a later change has superseded. It passes the opaque level, already clamped to what the model supports. Pi sets the startup or resumed level without the event, so a session start saves nothing.
- The plugin keeps two levels in memory: `chosen`, the last level reported by `onThinkingSelect`, and `landed`, the level a model switch left the session on when that differs from `chosen`. A thinking event whose level is `landed` is skipped; any other one becomes `chosen`, clears `landed` and is saved with `Host.saveDefaultThinkingLevel(level)`, which writes `defaultThinkingLevel` through the same `SettingsManager` path.
- A model switch resets the session's level from the running pi's in-memory settings (a per-model level, then the default loaded at startup), which do not see this extension's writes. On `onModelSelect` the plugin calls `Host.setThinkingLevel(chosen)`, pi clamps it to the new model, and the plugin records the result as `landed` when it is not `chosen`. So a switch never changes the saved level, the session returns to the chosen one, and a clamped level (`off` on a model without thinking) is never saved. Pi emits that call's event synchronously when the plugin's adapter handler comes first, before `landed` is known, so the plugin skips every thinking event while the call runs; when the event comes later it is either `chosen` itself (saved again, unchanged) or `landed` (skipped). The reset's own event is dropped by the adapter, and if it reaches the plugin after the switch's handler anyway it is either superseded or `landed`. Before any choice in the session `chosen` is unset, nothing is re-applied and the switch keeps pi's level, unsaved. Saving writes only the file, and pi emits nothing for file writes, so there is no loop. The selector offers only the levels the model supports, so Ctrl+S never asks for a clamped one; Ctrl+S on the level the session is already on changes nothing, so pi's own write is the only one and `chosen` stays where it was.
- Known limits. A `setModel` to the model the session is already on (Enter on it in the selector, `/model <current>`) still resets the level from pi's in-memory settings but emits no `model_select`, so the adapter's switch check cannot tell the reset from a choice: the session lands on the startup default and the plugin saves it. Pi does not expose its settings manager to extensions, so this extension cannot keep those in-memory settings current. Changing or removing a per-model thinking level in pi's settings calls `setThinkingLevel` for the current model, which reaches the plugin as a choice and is saved as the global default.
- The running pi's in-memory settings, and so the selector's `default` mark, see either change from the next session (`/new`, `/resume` or a restart). A project `.pi/settings.json` that sets `defaultModel` or `defaultThinkingLevel` still wins over the global default, as it does for Ctrl+S.
- A failed save is data: `saveDefaultModel` and `saveDefaultThinkingLevel` resolve to the error text, and the plugin shows it as a `pi-model-default: <ref> is not saved as the default model: <reason>` or `pi-model-default: <level> is not saved as the default thinking level: <reason>` warning through `HostUi.notify`. The session keeps the selected model or level either way.
- Only the main session drives it: the adapter never boots an extension inside a subagent session, and children get their model at creation, so a subagent's model or thinking level never reaches the default. Only `chosen`, `landed` and the re-apply flag are kept in memory.

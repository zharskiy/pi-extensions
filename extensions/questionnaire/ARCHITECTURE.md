# Questionnaire architecture

`index.ts` re-exports `api/extension.ts`, which builds the extension with `createManagedExtension` (namespace `pi-questionnaire`, no settings) and one plugin, `questionnairePlugin` in `api/plugin.ts`. The plugin registers the tool: its definition, the call checks and the awaiting-input signal come from `core/questionnaire.ts`, the types and the model-facing text from `core/questions.ts`, the form and the row from `ui/`. Its `enable` returns nothing to undo.

- Registers one tool, `questionnaire` (`modelOnly: true`, so codemode scripts cannot call it; `executionMode: "sequential"`, so two calls in one message never compete for the editor slot), with the description, `promptSnippet` and three `promptGuidelines` (decisions as concrete options, batch independent questions and defer dependent ones, fall back to a default or stop on cancel). Parameters are plain JSON schema: `questions: [{ id, label?, prompt, options: [{ value, label, description? }], allowOther? }]`. Only the main session has it: no extension boots inside an agent, and an agent that inherits the name finds no tool behind it.
- `execute`: outside tui mode, an empty batch, duplicate ids or a question with no options and `allowOther: false` return an `isError` result and show nothing (`checkCall`). Labels default to `Q1`, `Q2`… and `allowOther` to true. Otherwise it calls `host.ui.showForm` with the tool's signal and publishes `pi:awaiting-input` `{ source: "pi-questionnaire", waiting: true, title: "questionnaire" }` as soon as it starts waiting (before `showForm` waits for an open overlay such as `/agents` to close) and `waiting: false` exactly once when the form closes, `showForm` resolves without a form or the signal aborts.
- `ui/form.ts` is a pure reducer over `{ questions, tab, option, answers, typing }`. One question: no tab bar, Enter or a digit answers and submits. Several: Tab/→ and Shift+Tab/← move between the question tabs and a Submit tab (wrapping), ↑/↓/Home/End move the selection, digits `1`-`9` pick that option, Enter confirms (the tab keys are `tabStep` from `platform/ui-kit/tabs.ts`, the list keys `listKey` from `platform/ui-kit/list.ts`); an answer moves to the next unanswered question, then to the Submit tab, where Enter submits only when every question is answered. Coming back to a question selects its saved answer. `Type something.` (the last option while `allowOther`) opens the text input; Enter saves a non-empty, trimmed answer, Esc returns to the options (while typing, `pressKey` handles only Esc; `ui/view.ts` forwards every other key to the text input, and reopening the input pre-fills an earlier typed answer). Esc anywhere else cancels the form. Digits and Enter are ignored for the first 250 ms after the form opens (`pressKey`'s `armed` option, set by `ui/view.ts` from an injectable clock), so text typed ahead into the editor does not answer it.
- `ui/render.ts` draws it over `ThemeLike` only: accent rules above and below, the tab bar `← □ Scope  ■ Priority  ✓ Submit →` (`tabBar` from `platform/ui-kit/tabs.ts`; ■ success when answered, the active tab accent and bold, Submit success once complete), the wrapped prompt, the options with a `›` pointer and wrapped muted descriptions (`listLines` from `platform/ui-kit/list.ts`; rules and hints from `platform/ui-kit/key-hints.ts`), the text input under `Your answer:`, the Submit tab's answers (`(wrote)` for typed ones) with `Press enter to submit` or `Unanswered: …` in warning colour, and the key strip in pi's `key to verb` grammar (`↑↓ to select · 1-9 to pick · enter to submit · esc to cancel`, keys dim, words muted, wrapping between hints).
- Result text (`core/questions.ts`; error results carry the batch's questions in their details), one line per answered question in question order: `<label> (<id>): selected <n>. <option label> [value: <value>]` or `<label> (<id>): wrote: <text>`. A cancel (Esc, or the signal aborting) gives `User cancelled the questionnaire`, the answers given so far under `Answered before cancelling:`, and `Pick a sensible default for anything unanswered, or stop.` Details are `{ questions, answers, cancelled }`, so the row (`ui/summary.ts`, shell `row`) works from session files too: the title `questionnaire · N questions` after the call's mark, the answers under `↳`, one per line (`<label>: <n>. <option label>`, a typed answer followed by a dim `(wrote)`; labels in accent), a cancelled form `⊘ questionnaire · cancelled` with any answers given before, the error on the `↳` line in the error colour. Nothing is persisted.

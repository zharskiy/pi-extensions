# style architecture

- `index.ts` re-exports the default of `api/extension.ts`, which calls `createManagedExtension` with the namespace `pi-style` and one plugin, `stylePlugin` (`api/plugin.ts`). The plugin's `enable` loads the styles from `prompts/` under `ctx.paths.root`, wires the command and the session start, and returns nothing to undo. The settings are read by the plugin itself, not through the manager's `settings` option, because it needs the user and the project value apart. No bus, no services.
- Styles are the markdown files in `prompts/` (`concise.md` ships), read once when the extension loads by `loadStyles` (`core/styles.ts`); `normal` means no style. A file may start with YAML-style front matter (`---` lines) whose `description:` line is the short text shown in the picker; the front matter is stripped, the rest is the prompt section.
- `/style <name>` applies one through `Host.setPromptSection("output_style", text)` (`createStyleSection`, `core/style.ts`), `/style normal` passes `undefined`, so the main session and every agent at any depth get it from their next run (a run in flight finishes under the old one); pi sends only the changed section as a system patch. `/style` alone opens `selectForm` (`platform/ui-kit/select.ts`) through `HostUi.showForm` (`ui/pick.ts`): every style plus `normal`, each with its description beside the name, the current one marked `✓` and preselected; Enter or a digit applies the pick exactly like `/style <name>`, Esc changes nothing. Outside tui mode `/style` alone notifies the current and the available styles instead. An unknown name notifies an error. Commands run in the main session only.
- `pi-style.json` (`{ "style": "concise" }`, a `choice` over the styles plus `normal`) is read at each session start by `core/settings.ts` through `readSettingsFiles` (`platform/shared/settings-files.ts`), user file then trusted project file, each error warned once through `reportSettingsErrors`, and the stored style is re-applied. The command rewrites the user file `<agentDir>/pi-style.json` (a failed write warns, the style still applies); `api/plugin.ts` only wires these together; when the project file sets a style the new one still applies live, with a warning that the project file wins at the next session start.

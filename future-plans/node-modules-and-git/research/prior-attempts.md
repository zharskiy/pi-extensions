# What the two earlier attempts established about node_modules and .git

This digests the two research attempts in [future-plans/synced-workspace/](../../synced-workspace/README.md) for the two questions of this topic: `node_modules` and build output, and where `.git` lives and who runs git. It reports what the documents say, with no judgement. Where they differ, both are given.

Paths below are relative to `future-plans/synced-workspace/`, written `A1-arch` ([attempt-1-architecture.md](../../synced-workspace/attempt-1-architecture.md)), `A1-prog` ([attempt-1-progress.md](../../synced-workspace/attempt-1-progress.md)), and for attempt 2 the files in [attempt-2-live-share/](../../synced-workspace/attempt-2-live-share/ideal.md).

## node_modules and build output

- Attempt 1 states the goal as a monorepo of more than 1,000 Maven modules plus dozens of frontend repositories under one `workspaceRoot`, usable "without the `node_modules` scan" ([A1-prog](../../synced-workspace/attempt-1-progress.md), "Goal").
- Attempt 1's answer is `mounts.unsynced`: folder names, at any depth, that the sync leaves on each side. Default `node_modules` and `target`. Reason: dependencies and build output are per-system, so each side keeps its own ([A1-arch](../../synced-workspace/attempt-1-architecture.md), "The sync program").
- The rule is a fixed name list in pinata's configuration, not read from `.gitignore`. Reasons: `.pi/` is git-ignored yet must cross, and the agent can edit `.gitignore` ([A1-arch](../../synced-workspace/attempt-1-architecture.md), "The sync program"; [A1-prog](../../synced-workspace/attempt-1-progress.md), C1).
- Tracked files always cross. A listed name can be a source folder (a Java package `target`, a tracked `build/`); hiding it makes container git show its files deleted, and `git add -A` would stage that. Pinata asks git in the container (`git ls-files` with a pathspec, 4 ms on a small tree) and exempts those folders with Unison's `ignorenot` ([A1-arch](../../synced-workspace/attempt-1-architecture.md), "The sync program"; [A1-prog](../../synced-workspace/attempt-1-progress.md), S7 and V1).
- A folder deleted on one side is deleted on the other with everything in it, kept-out folders included. Deleting a module in the container removes the Mac's `target` under it ([A1-arch](../../synced-workspace/attempt-1-architecture.md), "The sync program"; [A1-prog](../../synced-workspace/attempt-1-progress.md), S7 "Deletion paths").
- Costs stated: dependencies and build output exist only in the VM and are rebuilt after `pinata restart`; the Mac's own build folders are untouched ([A1-arch](../../synced-workspace/attempt-1-architecture.md), Known limits 4 and 9). Other candidate names (`out`, `build`, `dist`, `.angular`, `.next`, `.gradle`, `.venv`) are per install; a frontend build folder left off is copied both ways and indexed by the editor (Decision 1).
- Attempt 2 reads Docker named volumes over a subfolder of the share as "useful, not a bound": untar 0.51 s against 5.6 s and 2 descriptors against 21,438, but the Mac sees an empty folder and the sources still fill the cache ([proposal.md](../../synced-workspace/attempt-2-live-share/proposal.md), "Rejected" table; [lab-b-notes.md](../../synced-workspace/attempt-2-live-share/lab-b-notes.md)).
- Attempt 2's ecosystem note ranks "split data classes" first: sources and `.git` on the share, regenerable trees (`node_modules`, `target`, `.gradle`, `dist`, `build`) on guest-local volumes. It says this reduces descriptors by the size of those trees and is not a bound. The IDE on the Mac then lacks `node_modules` (JS/TS resolution, run configurations) and `target`, unless installed or built on the Mac too, at the cost of disk. Marked inference and opinion ([notes-ecosystem.md](../../synced-workspace/attempt-2-live-share/notes-ecosystem.md), sections 8 and "Shortlist").
- Attempt 2's own design (live custom device) does not separate `node_modules`. It meets criterion 5, "the same files, the whole workspaceRoot, no copies" ([ideal.md](../../synced-workspace/attempt-2-live-share/ideal.md), "The eight criteria").

## .git

- Attempt 1 keeps exactly one `.git` per repository, the Mac's. At launch pinata lists repositories under the root (a directory holding a `.git` directory; lstat only, no git run) and binds each `<repo>/.git` from the VM's share into the agent container, nested inside the volume mount. The share then carries only `.git` traffic ([A1-arch](../../synced-workspace/attempt-1-architecture.md), "Parts" 2 and "Git").
- Reasons given: one index must be a single file for both sides, because with two each side would stage the other's commits as reverts (Known limits 1). Git state is then never copied. DDEV does the same, with the top-level `.git` kept on the host ([A1-prog](../../synced-workspace/attempt-1-progress.md), R1).
- `.git` is excluded from sync by name. Unison's patterns cannot tell a `.git` file from a `.git` directory ([A1-prog](../../synced-workspace/attempt-1-progress.md), S3).
- Pinata runs no git on the host, because the sandbox can write `.git/config` ([A1-prog](../../synced-workspace/attempt-1-progress.md), C1; [A1-arch](../../synced-workspace/attempt-1-architecture.md), "Git on the host: unchanged").
- Container git settings, passed by `GIT_CONFIG_COUNT` so they outrank the shared config: `core.checkStat=minimal`, `core.trustctime=false`, `core.ignorecase=false` (the Mac's `true` hides case twins on Linux), `safe.directory=*` (owner shows as whoever touched it last), and `GIT_OPTIONAL_LOCKS=0` ([A1-arch](../../synced-workspace/attempt-1-architecture.md), "Git").
- Mac settings recommended, not written: the same two `core` settings globally and `GIT_OPTIONAL_LOCKS=0` in the shell profile. Without the two settings every `git status` on either side rewrites every index entry (40,000 files: 0.8 s on the Mac, 4 s in the container). With them, background rewrites stop; the variable stops a Mac `git status` from rewriting the index (96 of 144 statuses without it, 0 of 30 with it). IDEA sets the variable by default since 2019.1 (read in source) ([A1-arch](../../synced-workspace/attempt-1-architecture.md), "Git"; [A1-prog](../../synced-workspace/attempt-1-progress.md), "Mac git rewrite" run near the end).
- Must stay off in shared config: `core.untrackedCache`, `core.fsmonitor`, `feature.manyFiles`; each makes both sides rewrite the index on every status ([A1-prog](../../synced-workspace/attempt-1-progress.md), S1 and R2). Split index and `skipHash` are safe on git 2.40 or newer (R2).
- The half-second window: when Mac git replaces a file in `.git` by rename (index on add, commit, checkout, reset; refs on commit and pull), the container cannot read it for 440 to 500 ms (14 of 14 tries; also 0.3 to 1.0 s in S1). A missing ref fails loudly. A missing index reads as empty, so `git status` shows everything deleted and `git commit` records an empty tree without an error. Measured: 1 of 166 commits against a Mac `git status` loop every 2 s; in another run `commit -am` committed the deletion of all 40,006 files. History stays recoverable, `fsck` clean. Present in pinata today. Pinata does not guard against it, and "nothing pinata can set" removes it ([A1-arch](../../synced-workspace/attempt-1-architecture.md), Known limits 1; [A1-prog](../../synced-workspace/attempt-1-progress.md), S1 and the final verdict).
- Locks are honoured across the two systems. `add`, `commit`, `checkout` take `index.lock` and fail at once; a Mac commit can fail with "index.lock: File exists" while container git holds it. One lock collision per run in the long loop ([A1-prog](../../synced-workspace/attempt-1-progress.md), S1, R2).
- Worktrees: git records absolute paths. A worktree made in the container at a path only the volume has works, but `git worktree prune` on the Mac deletes its record; `git worktree lock` protects it but makes plain `git worktree remove` fail, so locking was dropped. Git's `gc` leaves unreachable worktrees alone for three months (measured). Subagent checkouts at `<cwd>/.pi/worktrees/<id>` do not cross the sync; their branches live in the shared `.git` ([A1-arch](../../synced-workspace/attempt-1-architecture.md), "What is deliberately not covered"; [A1-prog](../../synced-workspace/attempt-1-progress.md), S1, S7, C2).
- Submodules and linked worktrees made on the Mac have a `.git` that is a file; it does not cross, so that folder is not a repository on the Linux side. Submodule `.git` files resolve through the shared `.git` in S1. Supporting submodules means walking inside repositories at launch, a full directory walk of the root ([A1-arch](../../synced-workspace/attempt-1-architecture.md), "What is deliberately not covered" and Decision 3; [A1-prog](../../synced-workspace/attempt-1-progress.md), S1).
- A repository created or renamed during a session keeps its `.git` only in the volume until the next launch lists it ([A1-arch](../../synced-workspace/attempt-1-architecture.md), "What is deliberately not covered").
- Hooks and config as a risk: a `.git` the sandbox can write runs code on the Mac the next time Mac git runs (`hooks`, `core.fsmonitor`, `core.sshCommand`, filters, aliases). Nothing protects it today and the threat model says so. `rm -rf <repo>` in the container empties the Mac's `.git` through the bind and the mirror then deletes the Mac's working files. Other agent sandboxes make `.git/hooks` and `.git/config`, or all of `.git`, read-only ([A1-prog](../../synced-workspace/attempt-1-progress.md), R2, C1, S7; [A1-arch](../../synced-workspace/attempt-1-architecture.md), "Host writes" and "`.git`"). krunkit's open RFC #977 asks for host-enforced write policy for `.git/hooks` and config ([notes-krunkit.md](../../synced-workspace/attempt-2-live-share/notes-krunkit.md)).
- Other git findings: the clock. Git protects same-second edits by comparing a file's time with the index's, assuming one clock. With the guest 1 to 3 s behind (simulated), a second same-size edit in the same second was missed 20 of 20 times. Names: a decomposed-Unicode name made on the Mac shows as renamed on Linux ([A1-prog](../../synced-workspace/attempt-1-progress.md), S1, R2, R6). Unison and Mutagen differ on keeping times: Mutagen never keeps modification times, so it fails the single-`.git` model (S2).
- Later mode: the volume filled by a clone inside the VM, mirror and `.git` binds optional. The open question is the editor ([A1-arch](../../synced-workspace/attempt-1-architecture.md), "Later: workspace not on the Mac at all").
- Attempt 2 keeps `.git` on the Mac inside the one live share. It says nothing about `.git` placement, `GIT_OPTIONAL_LOCKS`, `index.lock`, worktrees, submodules or the empty-commit window. It uses `git status` only as a load.

## Measurements

- Attempt 1 research machine (not named), repository of 40,001 files, Mac git 2.50.1, container git 2.39.5, working tree and `.git` both on Apple's share, today's layout: default `git status` rewrites all index entries each time, 0.75 to 0.86 s Mac, 3.6 to 4.6 s container. Window 458 to 498 ms after `git add`, 441 to 449 ms after a commit ([A1-prog](../../synced-workspace/attempt-1-progress.md), S1 and the later git run).
- Same repository, `.git` bound from the share inside a volume: cold `git status` 29 ms against 563 ms today; 20 host open files against 40,861. Open files for `.git` over the share are bounded by the number of files in it: 5,011 after `git log -p` on an unpacked repository, 909 once packed ([A1-prog](../../synced-workspace/attempt-1-progress.md), S1). Container `git commit` of 3,000 files adds 3,360 descriptors, back to 50 a minute later (S7).
- Unison on 300,010 files and 52,000 directories: first sync 253 s (while two other experiments ran), 180 to 200 MB per end, about 15 host descriptors, edit propagation 0.6 s (volume to Mac) and 1.3 s (Mac to volume), 5,000 files in about 5 s. Mutagen on 300,007 files: first sync 113 s, about 650 MB per end ([A1-prog](../../synced-workspace/attempt-1-progress.md), S2 and S3).
- Rehearsal on two repositories of 3,027 and 20 files, docker 29.5.2: commit visible on the other side in 1.4 s; 300-file branch switch settles in 0.7 to 2.2 s; mirror adds no host descriptors; 41 container commits against 88 Mac statuses in 3 minutes, none wrong ([A1-prog](../../synced-workspace/attempt-1-progress.md), S7).
- Attempt 2, this Mac (macOS 27.2, `kern.maxfiles` 122,880, `kern.maxfilesperproc` 61,440), a 19,491-file `node_modules` copy (304 MB, 21,420 inodes): Apple's share holds 1.00 descriptor per cached inode (21,432), released only on guest forget. VM ext4 and a docker volume use no host descriptors and are 35 to 44 times faster on untar and 77 times on cold `git status`. `npm ci` of 21,403 entries: 4.94 to 5.03 s on the share, with and without the governor ([track.md](../../synced-workspace/attempt-2-live-share/track.md), 01:30; [lab-b-notes.md](../../synced-workspace/attempt-2-live-share/lab-b-notes.md); [lab-d-notes.md](../../synced-workspace/attempt-2-live-share/lab-d-notes.md), T4). `rm -rf node_modules` plus `npm ci` on krunkit: 3.3 to 4.4 s and 10.3 to 12.6 s, descriptors flat at 123 ([lab-c-notes.md](../../synced-workspace/attempt-2-live-share/lab-c-notes.md)).
- Attempt 2, a 42k-inode repository (`git status`): 0.37 to 0.42 s ungoverned, 4.1 to 4.7 s at a governor budget of 30,000; not pruned at 50,000. After a Maven build `git status` is 358 ms on the hardened custom device against 778 ms on Apple's. Warm 245 to 296 ms on both ([track.md](../../synced-workspace/attempt-2-live-share/track.md); [ideal.md](../../synced-workspace/attempt-2-live-share/ideal.md), tables).
- Descriptors with 151,516 entries cached: custom device 10 lsof lines, Apple's share 53,631 ([ideal.md](../../synced-workspace/attempt-2-live-share/ideal.md), "Answer").
- File counts of the real workspace, of its `.git` and of its `node_modules`: not measured by either attempt. The failing machine was never measured ([README.md](../../synced-workspace/README.md), "Open points"; [A1-prog](../../synced-workspace/attempt-1-progress.md), V1 "Step 0"). Attempt 2 guesses "a few hundred thousand files" for sources plus `.git`, "must be measured with find|wc" ([notes-ecosystem.md](../../synced-workspace/attempt-2-live-share/notes-ecosystem.md), section 8). Pinata's `init` counts `.git` entries two levels deep only ([A1-prog](../../synced-workspace/attempt-1-progress.md), C1).

## Other projects

- DDEV: Mutagen, code in a docker volume, top-level `.git` on the host bind-mounted; tells users to run large git operations on the host. Pains: edits made while stopped go unseen until reset, lag on branch switches and mass deletes, conflicts, doubled disk, container writes up to 10 s to reach the host ([A1-prog](../../synced-workspace/attempt-1-progress.md), R1). Its docs say large `node_modules` makes Mutagen slow and recommend excluding it ([notes-ecosystem.md](../../synced-workspace/attempt-2-live-share/notes-ecosystem.md)).
- container-use, Sculptor, vibe-kanban, claude-squad: a git worktree or branch per agent. Docker Sandboxes "clone" and "mountless" modes: private clone. Codex cloud and Claude Code on the web: work returns as branches. None shows uncommitted agent edits live in the local IDE. Docker Sandboxes "direct" mode mounts live over virtiofs ([A1-prog](../../synced-workspace/attempt-1-progress.md), R1 and R4).
- Imbue's `mngr pair`: both-way Unison mirror of an agent's directory (R4). Tools that commit on every change bloat history and miss untracked files (R4).
- VS Code dev containers: a named volume over `node_modules`, or "clone in container volume" ([notes-ecosystem.md](../../synced-workspace/attempt-2-live-share/notes-ecosystem.md), sections 8; docs URL cited there).
- Docker Desktop synchronized file shares: Mutagen, `.syncignore`, ignored paths stop syncing and are not deleted, about 2 million files per share, paid (same note, section 2).
- OrbStack: `rm -rf node_modules` at 87% of native speed, pnpm install 88% (vendor figures); closed and paid (same note, section 3).
- Lima `limactl shell --sync`: rsync in and back with review; refuses VMs with host mounts, so unusable under colima ([A1-prog](../../synced-workspace/attempt-1-progress.md), R7).
- Other agent sandboxes make `.git/hooks` and `.git/config`, or all of `.git`, read-only (R2; source not named).

## Rejected options

- Attempt 1: Mutagen, no modification times, so the single `.git` fails (S2). Syncthing, too much machinery (R3). rclone bisync, DevSpace sync, docker-sync (R1). krunkit, experimental, a Mac rename of `HEAD` or the index can read as missing in the guest for up to 5 s, and per-OS dependency folders would still be shared (R5). `.gitignore` as the unsynced rule (above). Locking subagent worktrees (S7). Two `.git` per repository (Known limits 1). Keeping the workspace volume across `restart`, and a clock check in the helper, were not taken (V1). Sparse checkout would help every approach but is the repository owner's call (R4).
- Attempt 2: reverse sshfs, 2.6 to 3.2 times slower and no hard links, chown or xattr ([proposal.md](../../synced-workspace/attempt-2-live-share/proposal.md); lab B). Two-way Unison and Mutagen, citing attempt 1's figures only, not re-tested. NFS from the Mac, not measured, needs sudo and exposes nfsd to the guest ([notes-nfs.md](../../synced-workspace/attempt-2-live-share/notes-nfs.md)). Sources on guest ext4 with the Mac reaching them over a network mount, since IDEA has no native watcher there; JetBrains remote development, since the IDE would no longer be Mac-local ([notes-ecosystem.md](../../synced-workspace/attempt-2-live-share/notes-ecosystem.md), section 7). Docker Desktop, since the VM and its shares are not pinata's ([ideal.md](../../synced-workspace/attempt-2-live-share/ideal.md)).
- No document considered a git shim, a filter filesystem or a clone inside the VM as a solution to `.git` ownership, other than the "Later" clone mode above.
